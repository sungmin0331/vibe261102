| 상태 | 설계 단계 (구현 전) |

## 1. 개요

### 1.1 배경
하루 단위로 해야 할 일을 빠르게 적고, 완료 여부를 체크하며, 오늘의 진행 상황을 한눈에 확인할 수 있는 가벼운 웹페이지가 필요하다. 복잡한 프로젝트 관리 도구가 아니라 **"오늘"에 집중하는 단순한 도구**를 목표로 한다.

### 1.2 목표
- 3초 안에 할일 하나를 추가할 수 있다.
- 별도 설치·로그인 없이 브라우저에서 바로 사용할 수 있다.
- 새로고침하거나 브라우저를 다시 열어도 데이터가 유지된다.
- 데스크톱과 모바일 모두에서 편하게 사용할 수 있다.

### 1.3 비목표 (이번 범위에서 제외)
- 회원가입/로그인, 여러 기기 간 동기화
- 팀 공유, 협업 기능
- 반복 일정, 캘린더 연동, 푸시 알림
- 서버/데이터베이스 구축

- **학생 B**: 휴대폰으로 오늘 공부할 과목과 과제를 빠르게 체크하고 싶다.

## 3. 기능 요구사항

### 3.1 헤더 / 오늘 날짜 (P0)
- 상단에 오늘 날짜를 표시한다. 예: `2026년 11월 2일 (월)`
- 페이지 제목: "오늘의 할일"

### 3.2 할일 추가 (P0)
- 상단 입력창 + "추가" 버튼.
- Enter 키로 추가 가능, 추가 후 입력창은 비워지고 포커스 유지.
- 공백만 있는 입력은 무시한다.
- 최대 길이: 200자 (초과 시 입력 제한).
- 새 항목은 목록 맨 위(또는 맨 아래 — 결정 필요, §9 참고)에 추가.

### 3.3 할일 목록 표시 (P0)
- 각 항목: 체크박스, 내용, 우선순위 표시, 삭제 버튼.
- 완료 항목은 취소선 + 흐린 색으로 표시.
- 목록이 비어있으면 빈 상태 안내 문구 표시: "오늘 할 일을 추가해보세요".

### 3.4 완료 토글 (P0)
- 체크박스 클릭 시 완료/미완료 전환.
- 완료 시각(`completedAt`)을 기록한다.

### 3.5 수정 (P0)
- 항목 텍스트를 더블클릭(모바일: 길게 누르기 또는 편집 아이콘)하면 인라인 편집 모드.
- Enter 또는 포커스 해제 시 저장, Esc 시 취소.
- 빈 문자열로 저장하면 삭제 확인을 띄운다.

### 3.6 삭제 (P0)
- 항목별 삭제 버튼.
- 삭제 후 약 5초간 "되돌리기" 토스트 제공 (P1).

### 3.7 진행률 (P1)
- "3 / 7 완료" 텍스트와 진행 바 표시.
- 모든 항목 완료 시 축하 메시지 표시.

### 3.8 필터 (P1)
- 탭: 전체 / 진행중 / 완료
- 선택한 필터는 새로고침 후에도 유지.

### 3.9 우선순위 (P1)
- 높음 / 보통(기본) / 낮음 3단계.
- 색상 점 또는 라벨로 표시, 클릭 시 순환 변경.

### 3.10 완료 항목 일괄 삭제 (P1)
- "완료 항목 지우기" 버튼, 실행 전 확인.

### 3.11 순서 변경 (P2)
- 드래그 앤 드롭으로 순서 변경 (키보드 대안: 위/아래 이동 버튼).

### 3.12 날짜 전환 처리 (P2)
- 날짜가 바뀐 뒤 처음 접속 시, 어제 미완료 항목이 있으면 "어제 못 끝낸 N개를 오늘로 가져올까요?" 안내.
- 가져오기 / 버리기 선택 가능.

- 터치 대상 최소 44×44px.

## 6. 데이터 설계

### 6.1 Todo 모델
```ts
interface Todo {
  id: string;            // crypto.randomUUID()
  text: string;          // 1~200자
  completed: boolean;
  priority: 'high' | 'normal' | 'low';
  order: number;         // 정렬 순서
  date: string;          // 'YYYY-MM-DD' (로컬 기준, 해당 할일의 날짜)
  createdAt: string;     // ISO 8601
  completedAt: string | null;
}
```

### 6.2 저장 구조 (localStorage)
| 키 | 값 |
|---|---|
| `todolist:v1:todos` | `Todo[]` JSON |
| `todolist:v1:settings` | `{ filter: 'all' \| 'active' \| 'done', lastOpenedDate: 'YYYY-MM-DD' }` |

- 키에 버전(`v1`)을 포함해 이후 스키마 변경 시 마이그레이션 가능하게 한다.
- 모든 읽기/쓰기는 `try/catch`로 감싸고, 실패 시 메모리 상태로 동작.
- 날짜는 사용자 로컬 타임존 기준으로 계산.
- 오늘(`date === today`) 항목만 기본 표시, 7일 지난 항목은 자동 정리(P2).

## 7. 기술 설계

### 7.1 기술 스택 (권장)
- **Vanilla HTML + CSS + JavaScript (ES Modules)**, 빌드 도구 없음.
- 이유: 기능 범위가 작고, 정적 파일만으로 배포·실행 가능하며 의존성이 없다.
- 대안: 기능이 커질 경우 Vite + React/TypeScript로 전환.

### 7.2 폴더 구조 (예정)
```
todolist/
├── prd.md              # 본 문서
├── index.html          # 마크업
├── css/
│   └── style.css       # 스타일, 테마 토큰
└── js/
    ├── app.js          # 진입점, 이벤트 바인딩
    ├── store.js        # 상태 관리 + localStorage 저장/로드
    ├── todo.js         # Todo 생성/수정/삭제 등 순수 로직
    ├── view.js         # DOM 렌더링
    └── date.js         # 오늘 날짜 계산·포맷 유틸
```

### 7.3 아키텍처
```
[사용자 이벤트] → app.js → store.dispatch(action)
                             │
                             ├─ todo.js (순수 함수로 상태 변경)
                             ├─ localStorage 저장
                             └─ subscribe → view.render(state)
```
- 단방향 데이터 흐름: 상태 변경은 `store`를 통해서만 수행.
- 액션: `ADD`, `TOGGLE`, `EDIT`, `DELETE`, `UNDO_DELETE`, `SET_PRIORITY`, `REORDER`, `CLEAR_DONE`, `SET_FILTER`, `CARRY_OVER`.
- 렌더링은 목록 전체를 다시 그리되, 항목 수가 많아지면 key(id) 기반 부분 갱신으로 최적화.

## 8. 성공 지표 및 인수 조건

### 8.1 인수 조건 (P0)
- [ ] 텍스트 입력 후 Enter 시 목록에 항목이 추가된다.
- [ ] 공백 입력은 추가되지 않는다.
- [ ] 체크 시 취소선이 적용되고 진행률이 갱신된다.
- [ ] 항목을 수정·삭제할 수 있다.
- [ ] 새로고침 후에도 목록과 완료 상태가 유지된다.
- [ ] 360px 너비에서 가로 스크롤 없이 사용 가능하다.
- [ ] 마우스 없이 Tab/Enter/Space/Esc만으로 추가·완료·수정·삭제가 가능하다.
- [ ] `<script>` 등 HTML 문자열을 입력해도 텍스트로 표시된다.

### 8.2 성공 지표
- 할일 추가까지 걸리는 시간 3초 이내
- 하루 평균 완료율 (완료 수 / 전체 수) 추적 가능

## 9. 미결 사항
1. 새 항목 추가 위치: 목록 **맨 위** vs **맨 아래** — 기본안: 맨 아래(작성 순서 유지).
2. 완료 항목을 목록 하단으로 자동 이동할지 여부 — 기본안: 이동하지 않음.
3. 지난 날짜의 할일을 볼 수 있는 "기록" 화면 필요 여부 — 이번 범위 제외, 차기 검토.
4. 배포 방식 (로컬 파일 실행 / GitHub Pages 등) — 구현 단계에서 결정.
