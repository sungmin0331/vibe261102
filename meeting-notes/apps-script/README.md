# Apps Script 설치 가이드

웹페이지의 회의록을 구글 스프레드시트에 저장하는 서버 쪽 스크립트입니다. 스프레드시트에 붙어 있는 Apps Script 웹앱으로 배포하며, 시트 접근 권한과 API 키는 이 스크립트에만 있습니다. 웹페이지에는 비밀 값이 들어가지 않습니다.

## 1. 스프레드시트와 스크립트 만들기

1. 구글 드라이브에서 새 스프레드시트를 만듭니다. (예: `회의록 DB`)
2. 메뉴 **확장 프로그램 → Apps Script**를 엽니다.
3. 기본 `Code.gs`의 내용을 지우고, 이 폴더의 파일을 같은 이름으로 만들어 붙여넣습니다.
   - `Code.gs`, `Sheets.gs`, `Ai.gs`
4. **프로젝트 설정(⚙) → "편집기에서 'appsscript.json' 매니페스트 파일 표시"**를 켠 뒤, `appsscript.json` 내용을 이 폴더의 파일로 바꿉니다.

## 2. 스크립트 속성 설정

**프로젝트 설정 → 스크립트 속성**에 추가합니다.

| 속성 | 필수 | 설명 |
|---|---|---|
| `SYNC_TOKEN` | ✅ | 웹페이지 설정에 입력할 동기화 토큰. 32자 이상의 무작위 문자열을 쓰세요. |
| `AI_ENABLED` | | `true`로 두면 AI 요약을 사용합니다. 기본은 꺼짐입니다. |
| `ANTHROPIC_API_KEY` | AI 사용 시 | Claude API 키 (`sk-ant-…`). |
| `AI_MODEL` | | 기본 `claude-opus-5-5`. 비용을 줄이려면 `claude-sonnet-5-5`. |
| `AI_EFFORT` | | 기본 `medium`. 요약이 자주 시간 초과되면 `low`, 품질이 부족하면 `high`. |
| `AI_DAILY_LIMIT` | | 하루 AI 요약 횟수 한도. 기본 `50`. |

토큰은 아무 곳에서나 무작위로 만들면 됩니다. 예를 들어 Apps Script 편집기에서 다음을 한 번 실행하고 로그를 확인하세요.

```js
function makeToken() { Logger.log(Utilities.getUuid() + Utilities.getUuid()); }
```

## 3. 시트 준비 (권한 승인)

편집기 상단에서 함수 `setup`을 선택하고 **실행**합니다. 처음 실행하면 권한 승인 창이 뜹니다.
실행이 끝나면 `Meetings`, `ActionItems` 시트가 생기고, 시스템용 `_SyncLog`, `_AiUsage`, `_Meta` 시트는 숨겨집니다.

## 4. 웹앱 배포

1. **배포 → 새 배포 → 유형: 웹 앱**
2. 실행 사용자: **나**, 액세스 권한이 있는 사용자: **모든 사용자**
3. 배포 후 나오는 **웹 앱 URL**(`https://script.google.com/macros/s/…/exec`)을 복사합니다.
4. 회의록 웹페이지의 **⚙ 설정**에서 URL과 `SYNC_TOKEN` 값을 입력하고 **연결 테스트**를 누릅니다.

> 회사 Google Workspace 계정만 쓰는 경우 "도메인 내 사용자"로 제한할 수도 있지만, 이 경우 브라우저 요청이 로그인 페이지로 돌아가 연결 테스트가 실패할 수 있습니다(PRD 미결 사항 1).

## 스크립트를 고친 뒤 다시 배포하기

**배포 → 배포 관리 → (연필) 수정 → 버전: 새 버전 → 배포**. 이렇게 하면 URL이 바뀌지 않습니다. "새 배포"로 만들면 URL이 새로 생깁니다.

## 토큰이 유출됐을 때

1. 스크립트 속성 `SYNC_TOKEN`을 새 값으로 바꿉니다. 이전 토큰은 즉시 거부됩니다.
2. 더 확실히 하려면 **새 배포**로 웹앱 URL 자체를 바꾸고, 이전 배포는 **보관**합니다.
3. 팀원들에게 새 URL·토큰을 알려 웹페이지 설정을 갱신하게 합니다.

## 시트 구조

| 시트 | 내용 |
|---|---|
| `Meetings` | 회의 1건 = 1행. `meeting_id` 기준으로 갱신(upsert)되고, 저장할 때마다 `version`이 1씩 올라갑니다. |
| `ActionItems` | 액션 아이템 1건 = 1행. 웹에서 지운 항목은 `deleted = TRUE`로 남습니다(필터로 숨기세요). |
| `_SyncLog` | 저장 요청 로그 (최근 약 5,000건) |
| `_AiUsage` | AI 요약 호출 시각·모델·토큰 수 |
| `_Meta` | 스키마 버전 |

- 열은 1행 헤더 이름으로 찾으므로 열 순서를 바꾸거나 오른쪽에 자체 열을 추가해도 됩니다. 헤더 이름은 바꾸지 마세요.
- 웹페이지가 원본입니다. 시트에서 직접 고친 내용은 웹에서 다시 저장할 때 덮어써집니다.

## 문제 해결

| 증상 | 확인할 것 |
|---|---|
| 연결 테스트: "서버 응답을 해석할 수 없습니다" | 배포의 액세스가 "모든 사용자"인지, URL이 `/exec`로 끝나는지 |
| "동기화 토큰이 올바르지 않습니다" | 웹페이지 토큰과 `SYNC_TOKEN`이 정확히 같은지 (앞뒤 공백 주의) |
| "웹페이지와 스크립트의 버전이 다릅니다" | 최신 `.gs` 파일로 바꾼 뒤 새 버전으로 다시 배포 |
| AI 요약 버튼이 안 보임 | `AI_ENABLED=true`, `ANTHROPIC_API_KEY` 설정 후 웹페이지 설정에서 연결 테스트 다시 실행 |
| AI 요약 "HTTP 400" | Apps Script **실행** 메뉴의 로그에서 Claude API 오류 내용을 확인 (모델 이름 등) |

## 로컬에서 시험하기

구글 계정 없이 스크립트를 시험하려면 Node.js로 에뮬레이터를 씁니다.

```bash
node dev/test-apps-script.mjs
```

```bash
node dev/dev-server.mjs 5174
```

개발 서버를 띄운 뒤 웹페이지 설정에 URL `http://localhost:5174/mock/exec`, 토큰 `dev-token`을 넣으면 됩니다. 이 서버의 AI 요약은 실제 Claude 호출이 아니라 받아쓰기 문장을 골라 만든 가짜 초안입니다.
